9  Quarto 发布到 GitHub Pages

本章把本地写好的 Quarto book 推送到 GitHub，借助 GitHub Actions 自动构建，发布到 GitHub Pages 供在线阅读。全程只使用 GitHub 自带的服务，无需额外服务器。内容只涉及 Quarto book 的部署，不涉及其他发布方式。

9.1 发布流程

GitHub Pages 是 GitHub 提供的静态网页托管服务，仓库里的静态文件通过 https://<用户名>.github.io/<仓库名>/ 直接访问，例如本笔记的 shiyu-hong.github.io/git-notes。Quarto book 构建出的 HTML 是纯静态文件，天然适合托管。完整流程：

  1. 构建：本地 quarto render 生成 docs/
  2. 推送：把源码推送到 main 分支
  3. 自动构建：GitHub Actions 重新构建，把产物发布到 gh-pages 分支
  4. 托管：GitHub Pages 从 gh-pages 分支提供访问

提示：构建在云端自动完成，你只需把源码推上去，这正是 GitHub Actions 的价值。

9.2 准备发布

推送前，先在本地确认两件事：环境已配好，构建能顺利通过。如此推送到 GitHub 后，云端 Actions 的构建才能一次成功。

  • 已完成 环境配置（身份信息、SSH 密钥已配置到 GitHub）
  • 本地构建通过：quarto render 能成功生成 docs/ 目录

构建命令：

quarto render

这一步用来验证构建有效——docs/ 正是之后要发布的内容，本地能生成，云端重新构建时才不至于在 quarto render 处报错。输出类似 Output created: docs\index.html 即视为成功；若报错，先在本地解决，再继续推送。

9.3 推送到 GitHub

9.3.1 新建仓库

  1. 登录 GitHub，点击右上角 + → New repository
  2. Repository name 填仓库名（如 git-notes）
  3. 选择 Public，不要勾选 README/.gitignore/license
  4. 点击 Create repository

注意：免费账户的 GitHub Pages 只支持公开仓库。创建时若勾选了 README 或 license，GitHub 会先建一个 initial commit，首次 git push 会被拒（报 fetch first），先 git pull origin main --allow-unrelated-histories 合并再推送即可，合并后仓库里会多出 GitHub 生成的 README/LICENSE 文件。

9.3.2 推送代码

在项目根目录初始化仓库并推送：

git init
git add .
git commit -m "feat: 初始化 Git 笔记 quarto book"
git branch -M main
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main

使用 HTTPS 则把 remote 地址换成：

git remote add origin https://github.com/<你的用户名>/<仓库名>.git

注意：这里使用 环境配置 配置好的 SSH 方式。SSH 与 HTTPS 任选其一，不要混用。

9.4 配置自动发布

9.4.1 编写工作流

在项目根目录创建 .github/workflows/publish.yml：

# 工作流名称，显示在 Actions 页面
name: publish docs

on:
  push:
    branches: [main]      # 触发条件：推送到 main 分支时运行

permissions:
  contents: write         # 授予工作流写仓库内容的权限，发布产物需要

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout    # 检出仓库源码
        uses: actions/checkout@v4

      - name: Setup Quarto   # 安装 Quarto（version 用 release 取最新稳定版）
        uses: quarto-dev/quarto-actions/setup@v2
        with:
          version: release

      - name: Render book    # 执行构建，产物输出到 docs/
        run: quarto render

      - name: Deploy to GitHub Pages   # 把 docs/ 发布到 gh-pages 分支
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./docs

提示：# 注释已解释各行作用，核心三步：检出 → 构建 → 发布。version 用 release 取最新稳定版，latest 不是合法值。

把工作流提交并推送：

git add .github/workflows/publish.yml
git commit -m "ci: 添加 GitHub Pages 发布工作流"
git push

注意：首次运行需下载 Quarto，可能耗时一两分钟。

9.4.2 开启 Pages

工作流首次发布成功后，还需要让仓库从 gh-pages 分支提供页面：

  1. 打开仓库的 Settings → Pages
  2. 在 Source 处选择 Deploy from a branch
  3. Branch 选择 gh-pages，目录选择 / (root)
  4. 点击 Save

设置完成后，页面会显示访问地址：https://<用户名>.github.io/<仓库名>/。以本笔记为参考，成品在 shiyu-hong.github.io/git-notes，源码见 github.com/shiyu-hong/git-notes。

提示：设置页的「Learn how to add a Jekyll theme」是通用提示，与本项目无关；gh-pages 分支里的 .nojekyll 空文件（发布 action 自动生成）已让 GitHub 按静态文件直接服务。

9.5 验证与维护

9.5.1 确认清单

发布完成后依次确认：Actions 页面 publish docs 显示 ✅；Pages 设置页显示 Your site is live；浏览器打开「开启 Pages」里的访问地址，能看到笔记首页。

之后每次改动，用同一套流程推送即可，Actions 会自动重新部署：

git add .
git commit -m "docs: 更新某章节"
git push

9.6 排查常见问题

gh-pages 分支没生成时，先到 Actions 页面看最近一次 publish docs 的运行：若显示 ❌，点进该运行，查看标红步骤的日志，再对照下面排查。

9.6.1 Actions 页面找不到工作流

publish.yml 没有提交，或没推送到 main 分支。确认文件在 .github/workflows/ 下，重新提交并推送一次即可。

9.6.2 Setup Quarto 步骤失败

version: latest 不是 quarto-dev/quarto-actions/setup 的合法值，action 会去下载 vlatest 的安装包导致 404。把工作流里的 version 改成 release，提交并推送：

git add .github/workflows/publish.yml
git commit -m "ci: 修复 Quarto 版本参数"
git push

9.6.3 构建失败

常见是构建时下载 Quarto 超时，或工作流写错。点进失败的 job 看日志；若是超时，在 Actions 页面点击 Re-run all jobs 重跑即可。

9.6.4 gh-pages 分支没生成

工作流失败时发布步骤不会执行，成功（✅）后分支才出现。先修好失败步骤，再推送一次。

9.6.5 github.io 网页找不到

访问地址打不开，多数是 Settings → Pages 的 Source 没选 gh-pages 分支，或没点 Save。若仓库名恰好是 <用户名>.github.io，页面会部署到根域名 https://<用户名>.github.io/，地址里没有仓库名，用根域名访问。

9.7 总结

步骤 操作
建仓库 GitHub → New repository（选 Public）
本地构建 quarto render 确认无报错
推送源码 git init + add + commit + push
自动构建 .github/workflows/publish.yml
开启页面 Settings → Pages → 选择 gh-pages 分支

至此，您的 Git 笔记已经可以在线访问了。
